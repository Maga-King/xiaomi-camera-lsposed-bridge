# 外部素材与复原方法

## 为什么仅源码不等于完整可刷版

最新发布当时依赖已验证的 container-r1 APK 基线，编译指定 Java helper 后合并到自有 Smali，再生成 classes4.dex；不是从零重编译整个相机。本次完整发布在 Release 附带 r17 基线，包含其余第三方 dex、运行资源和算法；Actions 使用仓库最终 Smali 和 native 源码重建可用模块，而非要求用户寻找旧电脑上的依赖。签名私钥仍不分发。

`historical/native-r17-build/Build-NativeModule.ps1` 保留了原来的输入、编译选项和步骤。里面工作目录是历史布局，用户目录已替换为 `YOUR_USER`。不要直接在自己的电脑盲跑；先根据下表配置自己的文件和签名。

## 模型与算法输入

| 输入 | 在最终增量 APK 中的位置 | 说明 |
| --- | --- | --- |
| libmialgo_monopan.so | lib/arm64-v8a/ | M3 Monopan 原生算法 |
| libmialgo_m9runtime.so | lib/arm64-v8a/ | M9 runtime；历史脚本有四处精确指令补丁，必须匹配原件 |
| libQnnHtp.so、libQnnSystem.so、libQnnHtpV79Stub.so、libQnnHtpV79Skel.so | lib/arm64-v8a/ | 匹配 V79 的 QNN/HTP 环境，不可当作其他 DSP 的通用包 |
| styletrans_low_v81_arch79.bin、styletrans_high_v81_arch79.bin、styletrans_colorfix_v81_arch79.bin | assets/legendary/models/ | M9 模型，来自相应徕卡 donor 的 odm/etc/camera/m9s2style |
| leica_m9s2_param.bin | assets/legendary/models/ | 来自相应 donor 的 odm/etc/camera |
| leica-135.zip | assets/legendary/watermarks/ | 配套水印资源 |
| libanc_single_bokeh.so、libc++_shared.so | lib/arm64-v8a/ | 原算法依赖与匹配 NDK 运行库 |

上述第三方模型和闭源算法不直接提交 Git，大文件放在 `native-r17-materials` Release，Actions 自动获取。历史输入 donor 布局为 `m9-savebridge-7604-portable/system/odm/`，取材路径保留在构建脚本里。分发不改变其权利归属，替换时仍需要有权使用、ABI 匹配的材料。

## 自有 native 部分

- `legend_pixel_codec.cpp` → `liblegend_pixel_codec.so`，JNI 像素转换。
- `legend_raw_pack.cpp` → `liblegend_raw_pack.so`，RAW 附件相关。
- `legend_native_worker.cpp` → `liblegend_native_worker.so`；虽以后缀 .so 打包，构建类型是可执行 PIE worker，不要改成普通共享库。
- `aps_jpeg_copy.cpp`、sphal/vndksupport shim 是较早兼容研究的一部分，应审计使用范围，避免全局替换系统库。

关键编译选项、需要导出的符号、16KB page size 与链接依赖均保留在历史构建脚本。

## 工程其他素材

完整 r17 基线保留运行所需 `oplus_common_*` TSV/Parcel/base64 参数、leica_filter_param.bin、text_enhance_yuv_v1.tflite 和美颜 JNI，避免造出能编译却缺资产的空包。它们是当时设备上的兼容素材，不是任意硬件通用标定数据。手机照片、抓取日志、会话文件及私钥不包括在内。不要填空文件假装算法加载成功。

最简单的公开复原入口是 `python ci/build_r17.py`：在 `.materials/` 解压 Release 素材，设置 ANDROID_HOME，安装 SDK build-tools 36.0.0 和 NDK 28.2.13676358；完整命令见 `.github/workflows/build.yml`。历史脚本用于理解演变过程，新的 CI 脚本没有作者机器路径依赖。

## 推荐复原顺序

1. 先以最终 Smali 对照 Java，尤其 HookEntry、保存容器、水印与 native bridge；不要覆盖稳定基线中的全部 helper。
2. 准备 SDK/NDK、Xposed/DexKit 编译依赖、自己有权使用的 donor 和基线 APK。
3. 编译窄范围 Java helper、native worker/codec；对原始 runtime 做精确补丁验证，不能对已 patch 文件重复套用。
4. 使用自有 Smali 快照核对最终 classes4.dex，合并 Manifest、模型和 native 库，zipalign 后使用自己的证书签名。
5. 仅在备份后的测试环境安装，核对 LSPosed 作用域与 Provider 调用方；先确认失败能保存原图，再确认 M3 mode=2 worker 完成及最终像素确实更新。
6. 最后回归徕卡风格、水印、方向、图库、普通/专业/视频、一加相机共存。不以“成功编译”“出现 M3 标签”代替成片检查。
